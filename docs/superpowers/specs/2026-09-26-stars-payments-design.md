# Оплата звёздами Telegram и бесплатный лимит «3 в сутки»

**Дата:** 2026-09-26
**Статус:** утверждён владельцем (решение от 25.09.2026, детали реализации делегированы)
**Базовый коммит:** `9d666ae` (`main`), ветка `feat/stars-payments`

---

## 1. Цель

1. **Оплата только звёздами.** Правило Telegram: цифровые товары в ботах продаются
   только за Telegram Stars (core.telegram.org/bots/payments-stars). Перевод по
   реквизитам USDT/VND/THB со скриншотом админу убирается целиком.
2. **Бесплатно — 3 скачивания за скользящие 24 часа** вместо трёх навсегда.

Логику скачивания (`bot/services/*`) не трогаем.

Рамка владельца: всё работает; кода минимум; мусор на сервере не остаётся; лишней
нагрузки нет.

## 2. Решения владельца

| Вопрос | Решение |
|---|---|
| Правило возврата в `/terms` | Возврат, если сервис не оказан (бот не смог скачать, поддержка не помогла); решает администратор |
| Что видит админ | Сообщение на каждую оплату и продление + тревога, если платёж не записан; список платежей в карточке пользователя |
| Подсчёт бесплатных | Журнал бесплатных скачиваний, скользящее окно 24 ч |
| Платёж во время простоя бота | При старте разобрать очередь: платежи обработать, остальное выбросить |

## 3. Найденные риски потери денег (закрываются этой работой)

1. **Антифлуд глотает платёж.** `ThrottleMiddleware` висит на всех сообщениях.
   `successful_payment` — тоже сообщение: пришло в течение 3 с после ссылки — отброшено,
   звёзды списаны, подписка не продлена. → Сообщения с `successful_payment` идут мимо троттла.
2. **Код звал `start_polling(drop_pending_updates=True)`, но в aiogram 3 этот параметр
   молча игнорируется** — очередь простоя на деле переигрывалась целиком (и старые
   ссылки, и всё остальное). Продление Telegram списывает сам в любой момент; известие,
   пришедшее во время перезапуска, терялось бы вместе со ссылками. Разбор из §6.5
   впервые реально выбрасывает старое и при этом сохраняет платежи. → §6.5.
3. **Отмена автопродления — по номеру ПЕРВОГО платежа подписки**
   (core.telegram.org/api/subscriptions: `provider_charge_id` первого платежа). → У каждого
   платежа хранится `subscription_charge_id`.
4. **Проверка перед оплатой не сверяет цену и подписку.** Документация не говорит,
   идут ли продления через `pre_checkout_query`. Если идут — сверка с текущей ценой или
   отказ «уже есть подписка» ломали бы продления всем. → Проверяются только валюта и
   метка заказа, без базы (заодно гарантирует ответ за 10 с).

### 5.3. Запросы

`bot/db/free_quota.py`:
- `reserve_free_download(session, user_id, now) -> int | None` — в одной транзакции:
  1) `DELETE` строк пользователя с `reserved_at <= now - FREE_WINDOW` (таблица не растёт:
  у пользователя в ней не больше `FREE_DOWNLOADS_PER_DAY` строк);
  2) один оператор `INSERT … SELECT … WHERE (SELECT COUNT(*) … WHERE user_id = ?) < limit
  RETURNING id`. Первый же оператор записи берёт write-lock SQLite, подсчёт идёт под ним —
  гонки за последний слот нет (та же гарантия, что описана в `bot/db/engine.py`).
  Возвращает id брони или `None` (лимит исчерпан).
- `refund_free_download(session, reservation_id) -> None` — `DELETE` по id. Повтор — no-op.
- `free_quota_status(session, user_id, now) -> FreeQuota(left: int, next_at: datetime | None)` —
  брони в окне; `next_at` = самая старая + 24 ч, только когда `left == 0`.

`bot/db/payments.py`:
- `apply_star_payment(session, *, user_id, payment) -> PaymentOutcome` — одна транзакция
  вызывающего: `INSERT … ON CONFLICT(telegram_payment_charge_id) DO NOTHING` в
  `star_payment` + `apply_subscription_change(days=30, key="stars:<charge_id>")`.
  `subscription_charge_id`: у первого платежа (`is_first_recurring` или не `is_recurring`) —
  свой номер; у продления — номер последнего невозвращённого первого платежа этого
  пользователя (если такого нет — свой). `PaymentOutcome(duplicate, is_first, subscription_until)`.
- `list_user_payments(session, user_id, limit)`, `get_payment(session, payment_id)`.
- `apply_refund(session, *, payment_id, admin_id, now) -> RefundOutcome` —
  условный `UPDATE … SET refunded_at WHERE id=? AND refunded_at IS NULL` +
  `apply_subscription_change(days=None, key="refund:<charge_id>")`. Повтор — no-op.

### 5.4. Миграция `scripts/migrate_20260926.py`

По образцу `scripts/migrate_20260913.py` (бэкап через `sqlite3.Connection.backup` с
проверкой чтения, `--database`, `--backup-dir`, коды возврата 0/1/2):
1. бэкап;
2. создать `free_download` и `star_payment` с индексами — через
   `Base.metadata.create_all(sync_engine, tables=[…])` из моделей, без дублирования DDL;
3. `ALTER TABLE users DROP COLUMN free_downloads_left`, если колонка есть (SQLite ≥ 3.35;
   в образе 3.46.1);
4. печать сделанного. Повторный запуск безопасен. Подписки, платежи, журнал загрузок
   не трогает.

**Страховка:** `init_db` при старте проверяет `PRAGMA table_info(users)`; если колонка
`free_downloads_left` есть — `RuntimeError("Сначала запусти scripts/migrate_20260926.py")`.
Иначе бот наполовину работал бы и падал на каждом новом пользователе (NOT NULL).

**Откат на старый образ:** `ALTER TABLE users ADD COLUMN free_downloads_left INTEGER NOT NULL
DEFAULT 3` — новые таблицы старому коду не мешают, бэкап восстанавливать не нужно,
платежи не теряются.

## 6. Поведение

### 6.1. Экран «👑 Подписка» (`menu:subscribe`, переезжает в `bot/handlers/payments.py`)

- Подписка активна: «Подписка активна до ДД.ММ.ГГГГ. Если оформлена звёздами — продлится
  сама; отменить автопродление: настройки Telegram → «Мои звёзды».» Кнопки покупки нет —
  Telegram разрешает одному человеку несколько подписок сразу, это двойное списание.
- Не активна: цена, автопродление каждые 30 дней, как отменить, «оплачивая, ты принимаешь
  условия — /terms». Кнопка-ссылка «⭐ Оформить за N ⭐» на ссылку-счёт.
- Ссылка-счёт: `createInvoiceLink(title, description, payload=SUBSCRIPTION_PAYLOAD,
  currency="XTR", prices=[LabeledPrice(amount=SUBSCRIPTION_PRICE_STARS)], provider_token="",
  subscription_period=2592000)`. Создаётся один раз на процесс и кэшируется в модуле
  (ссылка общая, плательщик определяется по `from_user`). Ошибка создания → текст «Оплата
  временно недоступна, попробуй позже» + лог; кэш не заполняется.

### 6.2. `pre_checkout_query`

Ответ сразу, без базы и сети кроме самого ответа: `ok = currency == "XTR" and
invoice_payload == SUBSCRIPTION_PAYLOAD`; иначе `error_message` «Счёт устарел — открой
«👑 Подписка» и оплати заново». Цену и наличие подписки не сверяем (§3.4).

### 6.3. `successful_payment`

1. Одна транзакция: `get_or_create_user` + `apply_star_payment`.
2. `duplicate` (повторная доставка того же платежа) → ничего не пишем пользователю и админу.
3. Пользователю: первый — «✅ Подписка оформлена, безлимит до ДД.ММ.ГГГГ; продлится
   автоматически, отменить — настройки Telegram → «Мои звёзды»»; продление — «🔄 Подписка
   продлена до ДД.ММ.ГГГГ».
4. Админу: «💰 N ⭐ — имя (@ник, id), первый платёж/продление, подписка до … UTC».
   Отказ доставки админу глушится (лог).
5. Исключение базы → `logger.exception` с id пользователя и `charge_id`; админу тревога
   «⚠️ Платёж не записан: id, N ⭐, чек <charge_id> — выдай 30 дней вручную»; пользователю
   «Оплата получена, подписку включит администратор; вопросы — /paysupport».

### 6.4. Антифлуд

`ThrottleMiddleware.__call__`: событие с непустым `successful_payment` проходит сразу
к хендлеру, без отметки времени.

### 6.5. Старт: разбор очереди простоя (`bot/__main__.py`)

Вместо `start_polling(drop_pending_updates=True)`:
1. `delete_webhook(drop_pending_updates=False)`;
2. цикл `get_updates(offset, timeout=0, limit=100, allowed_updates=dp.resolve_used_update_types())`
   до пустого ответа; апдейты с `message.successful_payment` — в `dp.feed_update`;
   остальные пропускаются; `offset = последний update_id + 1` (подтверждает выброс);
3. `start_polling` без сброса.
Ошибка разбора → исключение наружу, процесс падает, `restart: always` перезапускает
контейнер и повторяет разбор.
Ограничение: Telegram хранит очередь 24 ч; простой дольше — платёж не увидим (сверка через
`getStarTransactions` — вне объёма, §9).

### 6.6. Команды (`bot/handlers/info.py`)

`/support` — текст поддержки (тот же, что кнопка «✉️ Поддержка», без упоминания скриншота
оплаты); `/paysupport` — вопросы оплаты и возвратов, контакт `ADMIN_USERNAME`, «укажи дату
платежа»; `/terms` — условия (§8, текст утверждает владелец до выкладки). `set_my_commands`:
всем — `start`, `terms`, `support`, `paysupport`; админу дополнительно `admin`.
Роутер `info` подключается ДО `user` (там текстовый catch-all).

### 6.7. Бесплатный лимит в интерфейсе (`bot/handlers/user.py`)

- `_reserve_quota` возвращает id брони (`int | None`) вместо `bool`; возврат при провале —
  `refund_free_download(reservation_id)` в тех же точках, что сейчас (`_quota_action` не меняется).
- Строка квоты (приветствие, помощь): подписчик — без изменений; есть остаток — «🎁 Бесплатно:
  осталось <b>N из 3</b> на сутки.»; остатка нет — «⏳ Бесплатные на сутки закончились.
  Следующее — через <b>5 ч 12 мин</b>. С подпиской — без ограничений.»
- Профиль: «🎟 Бесплатно на сутки: <b>N из 3</b>» (+ «следующее через …» при нуле).
- Отказ на 4-е скачивание: «🚫 Бесплатные скачивания на сутки закончились. Следующее откроется
  через <b>…</b>. С подпиской — без ограничений 👇» + кнопки «👑 Оформить подписку»
  (`menu:subscribe`) и «🏠 Главное меню».
- «через …»: `format_wait(delta)` в `bot/utils/text.py` — округление вверх до минуты;
  «5 ч 12 мин», «3 ч», «12 мин»; меньше минуты — «1 мин».
- Клавиатура помощи получает кнопку «👑 Подписка».
- Удаляются: `_payment_details_text`, `cb_pay_details`, `cb_subscribe` (переехал),
  `get_payment_details_kb`, кнопка «💳 Показать реквизиты».

### 6.8. Админка (`bot/handlers/admin_payments.py`, новый роутер)

- Карточка: строка «🎟 Бесплатно за сутки: N из 3»; кнопка «💸 Платежи» (`admin:payments:<user_id>`).
- Экран платежей: последние `PAYMENTS_IN_CARD`: дата UTC · сумма ⭐ · первый/продление ·
  «↩️ возвращён». У невозвращённых — кнопка «↩️ Вернуть N ⭐ от ДД.ММ»
  (`admin:refund_ask:<payment_id>`); «👤 Карточка» (`admin:card:<user_id>`).
- Подтверждение: «Вернуть N ⭐ за платёж от …? Подписка будет снята, автопродление отключено.»
  → «✅ Вернуть» (`admin:refund_do:<payment_id>`) / «↩️ Назад».
- Исполнение: уже возвращён → тост «Уже возвращён»; иначе
  1) `edit_user_star_subscription(user_id, subscription_charge_id, is_canceled=True)` — ошибка
  только в лог (подписка могла уже кончиться/быть отменена), возврат продолжается;
  2) `refund_star_payment(user_id, charge_id)` — `CHARGE_ALREADY_REFUNDED` считается успехом,
  любая другая ошибка → экран «❌ Telegram отказал: …», база не меняется;
  3) `apply_refund` → экран платежей с отметкой.
- Каждый хендлер — проверка админа первой строкой (как в `admin.py`); мусор в
  `callback_data` → тихий `callback.answer()`.
- Ручная выдача «+7/+30» — без изменений.

## 7. Проверки

Обязательные тесты владельца:
1. тот же платёж дважды → подписка продлена один раз, строка платежа одна;
2. продление → дата сдвигается на 30 дней от текущего конца;
3. возврат → подписка снята (`subscription_until is None`), `refunded_at` заполнен; повтор — no-op;
4. 4-е скачивание за сутки → отказ; через 24 ч → снова можно;
5. неудачное скачивание не списывается.

Плюс: гонка за последний бесплатный слот — один победитель; `free_quota_status.next_at`;
`subscription_charge_id` продления = номер первого платежа; `pre_checkout` ok/отказ без базы;
`successful_payment` — ответы, уведомление админа, дубль молчит, тревога при сбое базы;
троттл пропускает платёж; разбор очереди скармливает только платежи и подтверждает offset,
при ошибке — старый путь; админ-возврат: отмена+возврат, «уже возвращён» = успех, иная
ошибка не меняет базу; миграция на старой схеме (таблицы, колонка удалена, подписки целы,
повтор безопасен) и страховка `init_db`; `format_wait`.

Существующие тесты, завязанные на `free_downloads_left`, переводятся на брони: хелпер
`_seed_user(…, free_left=N)` в `tests/test_user_handle_url.py` заводит `3 − N` броней в окне.

Живая проверка: владелец покупает подписку звёздами → уведомление админу → возврат из
админки → подписка снята.

## 8. Условия `/terms` (черновик на утверждение владельцу)

📄 Условия использования

1. **Что это.** Бот скачивает видео и фото по ссылкам из Instagram, TikTok, Facebook, Pinterest
   и YouTube и присылает их в чат.
2. **Бесплатно.** 3 скачивания за любые 24 часа. Неудачное скачивание не считается.
3. **Подписка.** {цена} ⭐ за 30 дней безлимитных скачиваний, оплата звёздами Telegram.
   Продлевается автоматически каждые 30 дней, пока ты её не отменишь: настройки Telegram →
   «Мои звёзды». После отмены работает до конца оплаченного срока.
4. **Возврат.** Если бот не смог скачать то, ради чего ты оформил подписку, и поддержка не
   помогла — напиши в /paysupport и укажи дату платежа. Решение о возврате принимает
   администратор. При возврате подписка отключается сразу.
5. **Ограничения.** Скачивается только общедоступное: приватные, удалённые и закрытые в
   регионе публикации недоступны. Соцсети меняют свои сайты — отдельные ссылки могут временно
   не скачиваться. Бесперебойная работа 24/7 не гарантируется.
6. **Контент.** Ты сам отвечаешь за использование скачанного: соблюдай авторские права и
   правила площадок. Бот не хранит файлы — они удаляются сразу после отправки.

## 9. Вне объёма (сознательно)

- Сверка с `getStarTransactions` (простой бота дольше 24 ч).

- Выручка в статистике админа.
- Идемпотентность ручной выдачи «+7/+30» (H-12, Task 31 — своя очередь).

## 10. Выкладка и уборка

1. Собрать новый образ; текущий пометить тегом отката.
2. Остановить бота → миграция в разовом контейнере с `--backup-dir` на хост → убрать из `.env`
   строки реквизитов, цен в валютах и `FREE_DOWNLOADS` → запустить.
3. Смоук: бот стартует, `/start` показывает «осталось 3 из 3», `/terms` отвечает.
4. Живая проверка владельцем (§7).
5. Уборка: висячие образы (`docker image prune -f`, только dangling) и прежний образ отката
   после подтверждения; из бэкапов БД хранится один свежий.

Выкладка — только после утверждения владельцем текста `/terms` и явного «да».
